# 常见问题

## 安装与运行

### Q: 启动时提示缺少 WebKit2GTK 怎么办？
**A:** Linux 系统需要安装 Tauri 的运行时依赖：
```bash
sudo apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev \
  libappindicator3-dev librsvg2-dev patchelf libssl-dev
```

### Q: macOS 提示"无法打开，因为无法验证开发者"？
**A:** 前往 **系统设置 → 隐私与安全性**，在底部找到 DBX 并点击"仍要打开"。或使用 Homebrew 安装：`brew install --cask dbx`。

### Q: Windows 安装后打不开？
**A:** 确保已安装 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。Windows 11 通常已预装，Windows 10 可能需要手动安装。

### Q: Docker 容器启动后无法访问？
**A:** 检查端口映射是否正确（默认 4224）。确保防火墙允许该端口。使用 `docker logs dbx` 查看日志排查问题。

### Q: 国内下载慢怎么办？
**A:** 
- Docker 镜像使用国内源：`docker.cnb.cool/dbxio.com/dbx:latest`
- GitHub Releases 可以考虑使用代理或镜像站
- CLI/MCP 包可通过 npm 镜像：`npm config set registry https://registry.npmmirror.com`

## 数据库连接

### Q: 连接 PostgreSQL 时报 SSL 错误？
**A:** 在连接配置中开启 SSL 选项。如果使用自签名证书，可能需要设置 `sslmode=require` 或添加 CA 证书。

### Q: 如何通过 SSH 隧道连接数据库？
**A:** 在连接编辑界面 → **SSH 隧道**选项卡，填写 SSH 主机、端口、用户名，选择密钥或密码认证方式。

### Q: 支持哪些数据库的 SSL 连接？
**A:** MySQL、PostgreSQL、MongoDB、Redis、ClickHouse、SQL Server 等均支持 SSL/TLS 加密连接。

### Q: MongoDB Atlas 连接字符串如何配置？
**A:** 使用标准 MongoDB URI 格式：`mongodb+srv://user:password@cluster.xxxxx.mongodb.net/database`。DBX 会自动识别 Atlas 和副本集连接。

### Q: 如何导入 DBeaver 或 Navicat 的连接配置？
**A:** 菜单栏 → **文件 → 导入连接**，选择 DBeaver 或 Navicat 的配置文件即可批量导入。

## MCP 集成

### Q: MCP 服务器启动后提示找不到连接？
**A:** MCP 服务器需要读取 DBX 桌面端保存的连接配置。确保：
1. DBX 桌面端已安装并至少配置过一个连接
2. MCP 服务器与桌面端在同一台机器上运行
3. 如果使用 DBX Web 后端，已设置 `DBX_WEB_URL` 环境变量

### Q: 如何限制 MCP 的可用连接和权限？
**A:** 在 DBX 桌面端 **设置 → MCP** 中：
- 管理连接白名单（勾选允许 MCP 访问的连接）
- 设置权限模式：只读 / 数据读写 / 完全访问

也可通过环境变量限制范围：`DBX_MCP_SCOPE_CONNECTION_IDS`、`DBX_MCP_SCOPE_CONNECTION_NAME`。

### Q: MCP 能否在生产数据库上执行写操作？
**A:** DBX 内置生产环境保护机制。即使权限模式允许写操作，在生产数据库上执行危险 SQL 前会弹出确认对话框。可通过 MCP 策略设置全局禁止生产环境写入。

### Q: Windows Portable 版如何使用 MCP？
**A:** 需要设置 `DBX_DATA_DIR` 环境变量指向 `DBX.exe` 同级的 `data` 目录（包含 `dbx.db` 文件的文件夹）。

## AI 功能

### Q: AI SQL 助手支持哪些模型？
**A:** 支持 Claude（Anthropic）、OpenAI（GPT 系列）、以及所有兼容 OpenAI API 的端点。也支持通过 Ollama 使用本地模型。

### Q: AI 生成的 SQL 是否安全？
**A:** DBX 内置 SQL 安全审查机制，执行前会检查 AI 生成的 SQL：
- 识别潜在的危险操作（DROP、TRUNCATE 等）
- 区分读写操作
- 生产环境额外提示确认

### Q: 如何配置自己的 API Key？
**A:** 菜单栏 → **设置 → AI**，填写 API 提供商、API Key 和模型名称。API Key 仅存储在本地，不会上传到任何服务器。

## 性能与限制

### Q: DBX 能处理多大的结果集？
**A:** 数据网格采用虚拟滚动技术，理论上可处理数百万行数据。实际性能取决于数据库查询速度和内存。默认分页大小为 200 行，可调整。

### Q: DuckDB 模式有什么优势？
**A:** DuckDB 是嵌入式分析引擎，特别适合：
- 本地 Parquet/CSV/JSON 文件即时预览
- 跨数据源联邦查询
- 大数据量的 OLAP 分析
- 无需额外安装或配置

### Q: JDBC Agent 与原生驱动的性能差异？
**A:** 原生 Rust 驱动（MySQL、PostgreSQL、SQLite 等）性能最优，延迟最低。JDBC Agent 通过 Java 桥接，适合没有 Rust 原生驱动的数据库，会有额外序列化开销，但对大多数使用场景影响很小。

## 安全

### Q: 数据库密码存储在哪里？
**A:** 密码使用 AES-256-GCM 加密后存储在本地数据库文件（`dbx.db`）中。加密密钥通过 PBKDF2 派生。

### Q: Web 版如何保证安全？
**A:** 
- 登录页面可设置访问密码保护
- 支持通过反向代理添加 HTTPS
- 建议在受信任的内网环境中使用
- Docker 部署时不暴露到公网，或通过 VPN/零信任网络访问

### Q: 云端同步功能是否上传数据？
**A:** 云端同步仅同步连接配置（不含密码）和用户偏好设置。实际数据库数据永远不会上传。
